# CsPlayer v0.1.7 设计大纲（规划中，细节待讨论）

> 状态：**大纲占位**。分享卡片与唱片墙的具体设计待下一轮讨论确定后，再展开为完整设计文档（体例同 `archived/V0.1.5_DESIGN.md`）。
> 版本路线：v0.1.6 体验优化（进行中）→ **v0.1.7 唱片墙展示 + 分享卡片（核心）** → v0.1.8 下载与格式转换（核心）。
> 反馈来源：`archived/v0.1.5_FEEDBACK.md`（分享、唱片架展示）；排期见 `V0.1.6_DESIGN.md` §2 / §11.1。

## 1. 定位

一个主题：**封面的呈现与传播**。两项反馈合并成版——**唱片架展示（唱片墙）**与**分享（卡片式）**，同属封面视觉链路、共享渲染与导出组件，一次设计、一起交付。

## 2. 范围（思路）

1. **分享卡片**（单曲 / 专辑 / 歌单）：以**图片卡片**形式分享——非链接、**无二维码**；前端生成卡片图片，导出/发送方式待定。
2. **唱片墙**：`ShelfPage` 收藏专辑的展示升级（现为普通封面网格）；可延伸**唱片墙分享**（把唱片墙生成卡片）。视觉与交互方案待定。

## 3. 暂定原则

- 分享形态 = **图片卡片**：不做链接分享、不做二维码、不含音频文件。
- 倾向**纯前端实现**（canvas / DOM 渲染导出），后端预期零改动（数据源复用 `libraryApi.*` 现有接口）。
- 与现有 7 套主题色兼容。

## 4. 非目标

1. 下载与自动转换格式（→ v0.1.8，见 `V0.1.6_DESIGN.md` §11.2）。
2. 链接式分享（反馈已明确否决）。
3. 音频文件 / 歌单打包分发：版权红线，永久不做。

## 5. 待讨论清单（下一轮确定）

- **分享卡片**：版式与尺寸、卡片内容元素、导出/发送方式、入口位置、单曲/专辑/歌单的差异处理。
- **唱片墙**：视觉风格、交互方式、排序/筛选、大收藏量下的性能边界。
- **共享边界**：卡片渲染是否复用唱片墙视觉；两者的组件拆分。

## 6. 预估

分享卡片 2–3 人日 + 唱片墙 3–5 人日 ≈ **5–8 人日**。设计细化后回填：方案对比与决策、任务划分（S0–Sn）、验收清单（体例同 `archived/V0.1.5_DESIGN.md`）。

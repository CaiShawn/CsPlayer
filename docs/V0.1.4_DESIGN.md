# CsPlayer v0.1.4 设计文档

相对 v0.1.3 的增量范围。基线见 `archived/V0.1.1_DESIGN.md` / `archived/V0.1.2_DESIGN.md` / `archived/V0.1.3_DESIGN.md`。
本版一项主题：**登录凭证持久化（浏览器存储方案）**。**当前代码未实现，本文档记录设计、决策与实施任务划分。**

> 版本路线：v0.1.2 设置模块（已完成）→ v0.1.3 搜索 + 右键菜单（已完成）→ **v0.1.4 登录凭证持久化**。

## 1. 目标

1. 后端进程重启后**免重新扫码**：浏览器保存网易云登录凭证，后端重启后由前端自动恢复会话。
2. 后端保持**不落盘凭证**：磁盘上不存在网易云登录态文件。

## 2. 背景与现状

| 现状 | 位置 | 问题 |
|------|------|------|
| 会话存内存 dict（sid → 网易云 cookie + user_id，TTL 7 天） | `app/core/session.py` `SessionStore` | 进程重启即全部失效 |
| 浏览器只存随机 sid（HttpOnly cookie `wyy_session`） | `app/routers/deps.py` `set_session_cookie` | sid 失效后无凭证可恢复，只能重扫码 |
| 登录成功时后端已拿到完整凭证但**未返回给前端** | `routers/auth.py` `qr_check` 只返回 `{status, user}` | 前端没有凭证可保管 |

痛点复现：重启 uvicorn → 任意接口 401 → 跳回登录页 → 重新扫码。

## 3. 方案对比与决策

| 维度 | A. 后端落盘（sessions.json） | B. 凭证存浏览器（localStorage） |
|------|------|------|
| 解决重启痛点 | ✅ sid 重启后仍有效 | ✅ 前端把凭证再交给后端即可 |
| 浏览器拿到什么 | 只有随机 sid（HttpOnly） | **完整网易云凭证**（MUSIC_U 等） |
| XSS / 恶意扩展风险 | 拿不到凭证 | localStorage JS 可读，**凭证可被偷** |
| 服务端磁盘风险 | 明文凭证落盘（需 0600 + gitignore） | 无 |
| 传输面 | 凭证仅登录时传输一次 | 凭证仅恢复会话时传输一次（不随每请求） |
| 换机器 / 重装后端 | 需重新扫码 | ✅ 凭证随浏览器走 |
| 后端改动量 | 小 | 小～中 |

**决策：采用 B（凭证存浏览器）。**

- 关键判断：CsPlayer 是本地单人 localhost 应用。B 的"后端无状态"收益在该场景有限，但用户明确不希望后端磁盘留下凭证文件；B 把凭证留在浏览器信任域，服务端零持久化。
- B 的代价（XSS / 浏览器扩展 / 共享浏览器 profile 可读 localStorage）由用户知情接受，记录于 §6。
- A（后端落盘）保留为备选方案，若 B 实际使用中出现"清浏览器数据频繁掉登录"等体验问题可再评估。

## 4. 功能范围

### 4.1 凭证存储（前端）

- 存储介质：`localStorage`，key：`csplayer.ncm.cred`（与 v0.1.2 偏好设置 `csplayer:prefs:*` 前缀风格一致）。
- 结构：

```json
{
  "v": 1,
  "cred": { "MUSIC_U": "...", "MUSIC_R_U": "...", "MUSIC_A_T": "...", "__csrf": "...", "NMTID": "...", "MUSIC_SNS": "" }
}
```

- 新增工具模块 `frontend/src/utils/cred.ts`：`loadCred()` / `saveCred(cred)` / `clearCred()`；
  读写全部 `try/catch`（storage 被禁用或内容损坏时静默降级为"需扫码"）。
- **保存时机**：扫码登录成功（`qrCheck` 返回 `status === 'success'` 且带 `cred`）。
- **清除时机**：
  1. 用户登出（`POST /api/auth/logout` 成功后）；
  2. 恢复会话失败（凭证已过期 / 校验 401）→ `clearCred()` 后进登录页。
- 有效性校验：`loadCred` 要求 `cred.MUSIC_U` 为字符串，否则视为无效。

### 4.2 后端 API 增量

| 方法 | 路径 | 变更 | 说明 |
|------|------|------|------|
| POST | `/api/auth/qr/check` | **响应扩展** | `status=success` 时响应新增 `cred` 字段（即 NCM cookie dict，`auth_service.qr_check` 已持有，router 层透传即可） |
| POST | `/api/auth/restore` | **新增** | 入参 `{cred: {...}}`；用凭证重建会话，免扫码 |
| POST | `/api/auth/logout` | 不变 | 前端登出时顺带 `clearCred()` |

`POST /api/auth/restore` 行为（`auth_service.restore(cred)`）：

1. 入参校验：`cred` 必须为 dict 且含 `MUSIC_U`，否则 401（`code=1001`，"凭证无效，请重新扫码登录"）；
2. 清洗：按 `core/session.py` 的 `COOKIE_ATTRS` 过滤 `Max-Age/Expires/Path` 等非 cookie 键（与登录链路 `_extract_cookies` 同规则）；
3. 校验凭证：复用 `auth_service._fetch_profile(cookie)`（内部 `user_account`；失败抛 401，原样透出"登录已失效"语义）；
4. 建会话：`sessions.create(cookie, profile.userId)`（内存，TTL 7 天，**不落盘**）+ `set_session_cookie`；
5. 返回 `{user: UserProfile}`。

> 该接口无需已有会话（它本身就是"造会话"的入口），其能力等同登录接口，属已接受的暴露面。

### 4.3 前端改动清单

| 文件 | 改动 |
|------|------|
| `src/utils/cred.ts` | 新增，见 4.1 |
| `src/api/index.ts` | `qrCheck` 类型加 `cred?: Record<string, string>`；`authApi.restore(cred)`（走 `http.post`，**不走** `requestWithAuth`，避免 401 触发登出回调造成循环） |
| `src/hooks/useQrLogin.ts` | 轮询 `status === 'success'` 时 `saveCred(res.cred)`，再回调 `onSuccess` |
| `src/stores/authStore.ts` | ① `fetchMe` 失败后兜底 `restoreCred()`：成功则视为已登录并 `dataVersion+1`，失败才置 `user: null`；② 新增 `restoreSession(): Promise<boolean>`（模块级 inflight 去重，防多请求并发 401 重复打 restore）；③ `logout()` 增加 `clearCred()` |
| `src/App.tsx` | `setUnauthorizedHandler` 先 `restoreSession()`，成功则留在当前页（依赖 `dataVersion` 触发页面自愈 / 用户点「重试」），失败才 `clear()` + 跳登录页 |

### 4.4 恢复时序

```text
冷启动（后端在线，会话仍有效）
  fetchMe → 200 → 正常进入（不触碰 cred）

后端重启后冷启动
  fetchMe → 401 → 触发 onUnauthorized(restoreSession) 且 fetchMe 兜底 restoreCred
    → POST /api/auth/restore（带 localStorage 凭证）
    → 后端校验 + 建新会话 + Set-Cookie wyy_session
    → 前端拿到 user → 静默进入主界面（不闪登录页）

会话中途失效 / 凭证过期
  任意接口 401 → restoreSession → restore 401 → clearCred + clear → 跳登录页扫码

用户登出
  POST /api/auth/logout + clearCred()（下次启动必须扫码）
```

## 5. 交互与状态

- 恢复过程**静默**：`initialized` 完成前沿用现有「正在检查登录状态…」过渡，不出现登录页闪烁。
- 恢复失败直接落在登录页二维码界面，无额外弹窗。
- 切换账号（`SwitchAccountModal` 扫新码）成功后以新凭证**覆盖**旧凭证（单凭证模型，见 §7）。

## 6. 安全权衡（记录在案）

| 风险 | 说明 | 接受理由 |
|------|------|----------|
| XSS 读取 localStorage | 凭证（MUSIC_U 等）JS 可读，可直接操作网易云账号 | 本地单人 SPA，不加载第三方脚本，XSS 面很小；用户知情接受 |
| 恶意浏览器扩展 | 同上 | 只装可信扩展；扩展本就能读页面一切 |
| 共享浏览器 profile | 同机他人用同一浏览器可读凭证 | 单人自用机器；与把凭证存后端磁盘相比只是信任域不同 |
| 凭证明文过传输层 | restore 请求体带凭证 | 仅 localhost HTTP，不出网卡 |
| restore 接口被滥用 | 拿到任意有效凭证即可建会话 | 能力等同登录接口；仅绑定 localhost |

不做的缓解（见 §7）：DPAPI/加密存储（防不了本机攻击者，收益有限）、HttpOnly 承载凭证（JS 不可写、无法由前端自持）。

## 7. 非目标（本版明确不做）

1. **凭证加密存储**：固定密钥加密防不了本机攻击者，只防误看，暂不做。
2. **多账号多凭证管理**：单凭证模型（后登录覆盖）；多账号并存留待后续版本与 `SwitchAccountModal` 一并设计。
3. **无状态模式（每请求带凭证）**：凭证仅在 restore 时传输一次，不随每个 API 请求携带，减小暴露面与改动量。
4. **后端会话落盘（方案 A）/ 混合方案**：作为备选记录于 §3，本版不实现。
5. **凭证自动续期**：MUSIC_U / MUSIC_A_T 过期后仍需扫码，属上游限制。

## 9. 验收清单

- [ ] 扫码登录成功后 `localStorage` 出现 `csplayer.ncm.cred`，内容含 `MUSIC_U`，无 `Max-Age/Expires/Path` 垃圾键。
- [ ] 重启后端进程，刷新页面 → **不出现登录页**，自动恢复进入主界面；`wyy_session` 被重新签发。
- [ ] 恢复接口对空 `cred` / 缺 `MUSIC_U` / 过期凭证均返回 401，前端清凭证并落在登录页。
- [ ] 登出后 `csplayer.ncm.cred` 被删除，刷新必须重新扫码。
- [ ] `restore` 不写任何磁盘文件；`sessions` 仍纯内存。
- [ ] `restore` 请求不触发前端 `onUnauthorized` 回调（不循环）。
- [ ] 多请求并发 401 只产生一次 `restore` 调用（inflight 去重生效）。
- [ ] **版本回归**：凭证全链路、凭证边界、无回归三项（§8 S2）全部通过。

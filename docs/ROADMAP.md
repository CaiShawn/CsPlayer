## v0.1.7 唱片墙展示 + 分享卡片（核心）

**主题：封面的呈现与传播。** 两项反馈合并成版，同属封面视觉链路、共享渲染与导出组件，一次设计、一起交付。

- **分享卡片**（单曲 / 专辑 / 歌单）：以**图片卡片**形式分享——非链接、无二维码、不含音频；前端生成卡片图片（canvas / DOM 渲染导出），后端预期零改动。与现有 7 套主题色兼容。
- **唱片墙**：`ShelfPage` 收藏专辑展示升级（现为普通封面网格）；可延伸**唱片墙分享**（把整面唱片墙生成卡片）。

**随版小改动**：最近播放支持单曲 → 跳转所属专辑 / 歌单；唱片架改为按需分页加载（首屏 50 张，逐批加载）。

**顺延项**：键盘音量调节（↑/↓）随快捷键扩展一并设计回归——需统盘分配全局按键，避开 `/`、`Ctrl+K` 等现有快捷键。

**待决（细化时定）**：卡片版式 / 内容元素 / 导出方式与入口；唱片墙视觉与交互、排序筛选、大收藏量性能边界；卡片与唱片墙的组件共享边界。

## v0.1.8 下载与自动转换格式 + 播放列表可钉住

### 主题一：下载与自动转换格式（核心，全栈）

反馈：**下载并自动转换格式**，候选库 [ncmdump](https://github.com/taurusxin/ncmdump)。技术不确定性最大的一版（跨语言依赖 + 后端新链路 + 版权边界 + 大文件 UX）。

- **先决问题**：目标场景是 (a) API 直链音频下载 + 统一转码、(b) 解密用户自备 `.ncm` 文件，还是 (c) 两者都要——结论直接决定集成路线。
- **集成路线候选**：后端 Python 流式下载 + `ffmpeg` 转码 / `ncmdump` CLI 或库（Windows 向，需评估跨平台替代）/ 前端 WASM 解密 + 浏览器下载（后端零改动、隐私最优）。
- **链路要点**：单曲流式下载接口（`?format=mp3|flac`）；歌单 / 专辑批量下载需任务队列 + 进度反馈（zip 打包）；VIP 音质「可播放 ≠ 可下载」的降级策略。
- **合规红线（先定死再开发）**：仅限用户有权收听的内容供个人离线使用，不做分享分发；README 加使用声明；整单批量下载默认关闭、设置中显式开启。
- **UX**：单曲右键「下载」+ 详情页批量入口；格式 / 音质默认值进设置；断点续传 v1 不做。

### 主题二：播放列表可钉住（前端创意，评审选定方案三）

- 队列面板两态：**默认抽屉**（现状）+ **钉住常驻**（图钉按钮，右侧占位、主内容缩窄不被遮挡，钉住态外点不收起）。
- 状态记忆进 localStorage 偏好前缀，刷新跟随；「清除本地数据」后回落默认。
- 待决：钉住态是否支持拖拽调宽；与歌词面板同开的排布（倾向两者都常驻、歌词贴其左侧）；窄窗是否自动退化为浮层。

### 小改动：播放队列右键「查看来源」

队列项右键可跳转来源对象（歌单 / 专辑详情页）；来源非具体对象时降级（倾向隐藏该动作）。
需要把 `queueSource` 由展示字符串升级为结构化 `{ kind, id, name }`（含会话快照向后兼容）。

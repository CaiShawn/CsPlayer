## 问题记录（BUG）

### 2026-09-24 · 扫码登录连续 502：SDK DNS 解析瞬时失败（约 15s 窗口）

**状态：已恢复（瞬时性故障）；归因完成，DNS 瞬断来源待定。**

**现象**：`POST /api/auth/qr/check` 连续 6 次 502（14:15:37–14:15:52），第 7 次轮询成功。SDK 噪声含 `Could not resolve hostname`、`[ERR] [object Object]`。

**归因**：SDK 自带网络栈（engine.dll）域名解析瞬时失败，请求未出网——**与应用代码、v0.1.6 改动无关**。

| 证据 | 说明 |
|------|------|
| `Could not resolve hostname` | 解析即失败，无网络往返 |
| `upstream=1次 4.1ms` | 立即失败（EAI 类错误），非超时/丢包 |
| 15s 窗口 6 连败后一次即成功（`upstream=2次 361.8ms` 链路正常） | 瞬时 DNS 不可用 |
| 失败时 `cookie: {}`、成功时 `[REDACTED]` | 同期脱敏改动工作正常，无因果 |

**为什么表现为「多次请求才成功」**：扫码登录本身 3s 轮询，窗口内轮询各产生一个 502；`qr_check` 直调 `ncm_call` 无自动重试（登录路径设计选择），恢复依赖下一轮轮询——DNS 一恢复即取到已扫码状态（803）。`[ERR] [object Object]` 是 SDK 的 JS 错误对象字符串化噪声，对外统一 502 文案。

**待定**（需当时机器网络状态，应用侧无法再区分）：代理/VPN 分流（SDK 自有网络栈不读系统代理设置）、网络接口切换 / 系统 DNS 短暂不可达、递归解析器抖动。

**日志特征备忘**：`/api/auth/qr/check` 周期性 502 + SDK 噪声 `Could not resolve hostname` + perf 行 `upstream=1次` 且 <10ms → 非应用问题（换网络/稍后重试；持续失败查代理分流与 DNS）。历史同类排查体例见 [`DEBUG.md`](DEBUG.md)。

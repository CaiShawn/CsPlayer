# CsPlayer v0.1.5 设计文档

> 📦 **本文档已封存**（2026-09 · v0.1.5 验收通过）。内容为 v0.1.5 最终实现基线，不再更新；后续主题见 [`V0.1.6_DESIGN.md`](V0.1.6_DESIGN.md)。

相对 v0.1.4 的增量范围。基线见 `V0.1.1_DESIGN.md` ~ `V0.1.4_DESIGN.md`（同在 `docs/archived/`）。
本版一项主题：**多账号凭证库（切换账号免扫码）**。**已实现（v0.1.5）**；本文档记录设计、决策与实施任务划分，实施中的决策补记见 §10。

> 版本路线：v0.1.3 搜索 + 右键菜单（已完成）→ v0.1.4 登录凭证持久化（已完成）→ **v0.1.5 多账号凭证库**。
> 依赖 v0.1.4 沉淀的凭证保管链路（`utils/cred.ts`、`POST /api/auth/restore`）；本质是把 v0.1.4 的**单凭证模型**升级为**多账号凭证库**。

## 1. 目标

1. **切换账号不再丢凭证**：登录过的每个账号的凭证都保留在浏览器里，切回旧账号**一键恢复、无需扫码**。
2. 凭证管理可控：可查看已保存账号、单独移除、一键清空；「退出登录」语义明确（彻底退出 = 吊销凭证）。
3. 维持 v0.1.4 两条底线：**后端零落盘**、凭证只存浏览器信任域。

## 2. 背景与现状

| 现状 | 位置 | 问题 |
|------|------|------|
| 凭证单槽存储 `csplayer.ncm.cred` = `{v:1, cred}`，`saveCred` **覆盖写** | `frontend/src/utils/cred.ts` | 扫新码即覆盖旧凭证，旧账号凭证永久丢失，切回必须扫码 |
| 切换账号 = 纯扫码流程（`useQrLogin` fresh 模式），成功后 `loginSuccess` 原地替换会话 | `components/layout/SwitchAccountModal.tsx` | 没有"选已保存账号"入口；注释明确「不先 logout」（正确，见 §3.3），但旧凭证被 `saveCred` 覆盖 |
| 冷启动/401 自动恢复只认一个凭证 | `stores/authStore.ts` `restoreSession()` | 恢复目标不可选；恢复失败 `clearCred()` 一刀切 |
| 登录页只有二维码 | `pages/LoginPage.tsx` | 凭证还在却只能重新扫码 |
| 设置「缓存」只有偏好重置/清除本地数据 | `pages/SettingsPage.tsx`（`clearLocalData` 只清 `csplayer:` 前缀，**不含** `csplayer.ncm.*`） | 已保存凭证无处查看、无法删除，隐私不可控 |
| 「退出登录」= 上游 `logout`（吊销 MUSIC_U）+ `clearCred` | `stores/authStore.ts` `logout()` | 多账号下语义需重新界定：吊销谁、移除谁 |

痛点复现：小号听歌 → 扫码切小号（大号凭证被覆盖）→ 想切回大号 → **再扫一次码**。

## 3. 方案对比与决策

### 3.1 凭证库放哪

| 维度 | A. 后端账号池（落盘多账号） | B. 浏览器多账号凭证库（本版） |
|------|--------------------------|-------------------------------|
| 切回旧账号 | ✅ | ✅ |
| 后端零落盘（v0.1.4 底线） | ❌ 磁盘上出现凭证文件 | ✅ |
| 浏览器暴露面 | 单凭证 | **N 个凭证**（爆炸半径变大，见 §6） |
| 后端改动量 | 大（文件存储/加密/清理） | 小（仅行为验证，见 §4.2） |
| 换浏览器 / 重装 | 凭证随服务端走 | 需重新扫码 |

**决策：B。** 延续 v0.1.4 的信任域判断（本地单人应用，凭证留在浏览器）；A 直接违反「后端不落盘凭证」的既有约束，且引入新的磁盘泄密面。

### 3.2 账号身份标识（判重 / 索引键）

| 候选 | 说明 | 结论 |
|------|------|------|
| `userId`（`UserProfile.userId`） | 扫码成功（`qr/check`）与恢复成功（`restore`）都返回，稳定唯一 | **主键** |
| `MUSIC_U` 全等 | 纯凭证侧可见，无需联网 | **兜底判重**（v1 迁移条目 userId 暂缺时用） |
| 昵称 / 头像 | 可改、可重复 | 仅展示，不作键 |

**决策**：条目以 `userId` 为键；判重规则 `userId` 相等 **或** `cred.MUSIC_U` 全等 → 视为同一账号**覆盖更新**（凭证刷新、昵称头像同步）。v1 迁移条目 `userId: 0`（暂缺）在首次 `restore` 成功后回填真实 `userId` 重写入库。

### 3.3 切换账号时旧会话/旧凭证怎么处置

| 维度 | a. 调上游 logout 再切 | b. 只替换会话，旧 sid 留待 TTL（现状） | c. 替换 + `sessions.delete(旧 sid)` |
|------|----------------------|--------------------------------------|----------------------------------|
| 旧账号凭证可用性 | ❌ **网易云 `/logout` 会吊销 MUSIC_U**，切回必扫码，与本版目标直接冲突 | ✅ | ✅ |
| 旧账号在途请求 | 全部 401 | 正常完成 | 401（切换竞态，见 §3.6） |
| 服务端会话残留 | 无 | 旧 sid 残留至 TTL（7 天，纯内存，量级可忽略） | 无 |

**决策：b。** 切换**绝不调用上游 logout**（v0.1.4 `SwitchAccountModal` 的「不先 logout」沿用并上升为规则）；旧 sid 留待 TTL 过期，换取**零 401 竞态**。c 记录为备选：若后续要做会话收紧，可加 `POST /api/auth/drop` 由前端在切换**完成且确认无在途请求后**再作废旧 sid。

> ⚠️ 依赖验证（S0-1）：需实测确认网易云 `/logout` 确实吊销 MUSIC_U（现有注释与直觉均指向是）。若实测**不**吊销，则 §3.4 的「彻底退出」需改为仅本地删除凭证。→ **结论见 §10.1**

### 3.4 「退出登录」语义（TopBar，产品决策）

| 候选 | 行为 | 结论 |
|------|------|------|
| **彻底退出（决策）** | 上游 logout 吊销**当前账号**凭证 + 从凭证库移除**当前条目** + 清会话/队列；**其余已保存账号不受影响**，登录页可一键切到别的账号 | ✅ 与 v0.1.4 验收语义「登出后刷新必须重新扫码」兼容（对当前账号成立），且语义可预期 |
| 软退出（保留凭证） | 只清本地会话，凭证保留 | ❌ 出现「退出了却刷新又登回来」的怪相，与 v0.1.4 语义冲突 |
| 彻底清空（移除全部账号） | 一次清库 | ❌ 多账号下过于粗暴，交给设置/弹窗的「清除全部凭证」 |

**决策：彻底退出（仅当前账号）**。UI 文案不变（「退出登录」），弹窗内每个账号提供「移除」（纯本地删除，不吊销）；「移除当前账号」等价走 `logout()`（需二次确认）。

### 3.5 冷启动自动恢复策略

| 候选 | 结论 |
|------|------|
| **只自动恢复 active 账号（决策）**：失败 → 落登录页，账号列表可见，由用户点选 | ✅ 可预期，不会「打开变成了另一个人」 |
| 失败后自动逐个尝试其余账号 | ❌ 身份不确定、时序不可预期；且首个可用账号未必是用户想用的 |

**决策**：自动恢复**只针对 active**；其余账号一律手动一键切换（`restore` 本身就是免扫码的，成本仅一次点击）。

### 3.6 手动切换 vs 401 自动恢复的竞态

场景：切换到 B 的瞬间，旧账号 A 的在途请求恰好 401 → v0.1.4 的 `setUnauthorizedHandler` 会触发自动恢复，可能把 active 抢回 A（或与手动 `switchAccount` 并发打两次 restore）。

**决策**：`authStore` 引入 `switching` 守卫（切换期间为 true）：

1. `setUnauthorizedHandler` 见 `switching` 直接挂起（不自动恢复、不跳登录页），切换结束后按新 active 自愈（`dataVersion+1` 触发页面重拉）；
2. 恢复去重从 v0.1.4 的**模块级单 inflight** 升级为**按目标账号去重**（`Map<userId, Promise>`）：并发 401 对同一账号只打一次 restore，而手动切换（目标不同账号）不被误合并；
3. `restoreSession` 成功落库前复查「目标账号仍是本次调用的目标」，防止过期结果覆盖新状态。

### 3.7 存储键与 v1 迁移

| 候选 | 结论 |
|------|------|
| **新键 `csplayer.ncm.accounts`（v:2）+ 一次性迁移 v1（决策）** | ✅ 语义清晰（存的是账号列表）、迁移路径明确、失败无副作用 |
| 沿用 `csplayer.ncm.cred` 升 `v:2` | 可行但键名（cred 单数）与内容长期错配 |

**决策**：新键 + 迁移。加载时若存在 v1 键：包成单元素 `accounts`（`userId: 0` 暂缺）→ 写新键 → 删旧键；任一步 try/catch 静默（失败下次再迁）。**「清除本地数据」继续不清 `csplayer.ncm.*`**（凭证由「账号凭证」卡片显式管理，见 §4.3 / §5.3）；备选「一并清除」记录在案，理由见 §6。

## 4. 功能范围

### 4.1 凭证库（前端存储模型）

- 存储介质：`localStorage`，key：`csplayer.ncm.accounts`（v1 迁移自 `csplayer.ncm.cred`）。
- 结构（envelope `v: 2`）：

```json
{
  "v": 2,
  "activeId": 123456,
  "accounts": [
    {
      "userId": 123456,
      "nickname": "昵称",
      "avatarUrl": "https://…",
      "savedAt": 1710000000000,
      "lastUsedAt": 1710000000000,
      "cred": { "MUSIC_U": "…", "MUSIC_R_U": "…", "MUSIC_A_T": "…", "__csrf": "…", "NMTID": "…", "MUSIC_SNS": "" }
    }
  ]
}
```

- 条目上限 **10**，超出按 `lastUsedAt` LRU 淘汰（**永不淘汰 active**）。
- 有效性校验：条目 `cred.MUSIC_U` 必须为非空字符串，否则整条视为无效丢弃（沿用 v0.1.4 规则）。
- 工具模块 `frontend/src/utils/cred.ts` **升级为多账号模型**（文件名不变，单凭证 API 退役）：

```ts
export interface SavedAccount { userId: number; nickname: string; avatarUrl: string
  savedAt: number; lastUsedAt: number; cred: NcmCred }

loadAccounts(): { activeId: number; accounts: SavedAccount[] }   // 含 v1→v2 迁移，损坏静默回空
loadAccount(userId?: number): SavedAccount | null               // 缺省 = active
upsertAccount(user: { userId; nickname; avatarUrl }, cred: NcmCred): SavedAccount
  // 判重（§3.2）覆盖 → 置 active → 刷新 lastUsedAt → LRU 裁剪
touchAccount(userId: number): void                              // restore 成功后刷新 lastUsedAt / activeId
removeAccount(userId: number): void
clearAccounts(): void
```

读写全部 `try/catch` 静默降级（storage 被禁/损坏 → 回落「需扫码」）。

- **保存时机**：扫码登录成功（`qrCheck` 返回 `status === 'success'` 且带 `cred`）→ `upsertAccount(res.user, res.cred)`（同号覆盖 = 凭证刷新；新号插入并切为 active）。
- **身份回填**：v1 迁移条目在 `restore` 成功（响应 `{user}`）后以真实 `userId` / 昵称 / 头像重写入库（`upsertAccount` 自动完成判重合并）。
- **移除时机**：
  1. 退出登录 → 移除**当前**条目（§3.4）；
  2. 恢复**该账号**失败（401 凭证过期）→ 仅移除**该条目**，其他账号不动（v0.1.4 的 `clearCred` 一刀切升级为按条目删除）；
  3. 用户在设置 / 切换弹窗手动「移除」；
  4. LRU 淘汰（超 10 个）。

### 4.2 后端 API 增量

| 方法 | 路径 | 变更 | 说明 |
|------|------|------|------|
| POST | `/api/auth/qr/check` | 不变（v0.1.4 已带 `cred` + `user`） | 前端据此 `upsertAccount` |
| POST | `/api/auth/restore` | 不变（入参 `{cred}`，返回 `{user}`） | **切换与自动恢复共用同一入口**；`{user}` 用于身份回填 |
| POST | `/api/auth/logout` | 不变 | 语义固定为「彻底退出当前账号」（上游吊销，§3.4） |
| — | `/api/auth/drop` | **本版不做**（备选，见 §3.3 c） | 作废本地 sid 用；等有会话收紧需求再引入 |

后端改动量：**小**。S0 以行为验证与契约确认为主（§8 S0），代码预期零改动～一行级改动；「不落盘、纯内存 sessions」不变。

### 4.4 关键时序

```text
切换账号（SwitchAccountModal 点已保存账号 B）
  switching = true（挂起 401 自动恢复，§3.6）
  → POST /api/auth/restore {cred: B.cred}   （http.post，不触发 onUnauthorized）
  → 200 {user}：
      touchAccount(B.userId)（activeId=B、lastUsedAt 刷新）
      likesStore.clear() + dataVersion+1 + user = B
      switching = false → 弹窗关闭，留在当前页（dataVersion 自愈）
  → 401：B 凭证过期 → 仅 removeAccount(B) → 弹窗内该条目标「登录已失效」+ 引导扫码
  → 其它错误：提示「切换失败，请重试」，不动凭证库，switching = false

冷启动（后端在线，active 会话仍有效）
  fetchMe → 200 → 正常进入（不触碰凭证库）

后端重启后冷启动
  fetchMe → 401 → fetchMe 兜底 restoreSession(active) ／ onUnauthorized 同目标去重合并
    → POST /api/auth/restore（active 凭证）→ 200 → 静默进入主界面（不闪登录页）
    → 401 → 仅删除 active 条目 → 落登录页（其余账号在「快速登录」可见）

手动切换 vs 在途 401（竞态）
  switching=true 期间 onUnauthorized 直接返回；切换完成后统一按新 active 恢复

用户退出登录（当前账号 A，另有 B/C 已保存）
  POST /api/auth/logout（上游吊销 A）→ removeAccount(A) → 清会话/队列 → 登录页
  登录页显示 B/C 快速登录（A 已不在；A 需重新扫码）

v1 升级首次加载
  检测 csplayer.ncm.cred → 包成 accounts=[{userId:0,…}] 写 csplayer.ncm.accounts → 删旧键
  → 冷启动 restore 成功 → 回填真实 userId/昵称/头像入库
```

## 5. 交互与状态

### 5.1 SwitchAccountModal（重构）

```text
切换账号
├─ 已保存账号（点头像行即切换，免扫码）
│   ├─ [头像] 昵称 · UID:xxxxx        [使用中·禁用 | 切换中… | 移除]
│   └─ …
├─ [ + 扫码登录其他账号 ]（展开原二维码流程，成功即入库并切换）
└─ 提示行：凭证保存在本机浏览器，可随时移除
```

- 每条目 hover/常驻「移除」（本地删除，不吊销）；移除当前账号 → 提示走「退出登录」（二次确认后等价 `logout()`）。
- 切换中：目标条目转圈、全部条目禁用；失败区分「登录已失效（401）」与「切换失败请重试（其他）」。
- 扫码成功后**列表原地刷新**（新号插入 / 同号凭证覆盖）并自动切换，沿用 v0.1.4「替换会话、不先 logout」。

### 5.2 LoginPage（增量）

- 存在已保存账号时，二维码上方出「快速登录」区块（头像 + 昵称，点击即 `switchAccount` → `/home`）；无账号时与现状完全一致。
- 目标凭证过期：该条目即时移除并提示「登录已失效，请重新扫码」，二维码区保持可用。
- v0.1.4 行为保留：恢复过程静默、失败直接落在二维码界面，无弹窗。

### 5.3 设置 · 「账号凭证」卡（新）

- 位置：「歌词」与「缓存」之间，`SettingSection id="accounts" title="账号凭证" desc="本机保存的登录凭证管理"`。
- 内容：账号列表（头像、昵称、UID、上次使用时间）+ 每行「移除」+ 卡底「清除全部凭证」（二次确认）。
- 说明文案（沿用 v0.1.2 风格）：「凭证保存在本机浏览器（localStorage），不上传后端；移除后需重新扫码」。
- **边界重申**（§3.7）：「缓存 → 清除本地数据」仍只清 `csplayer:` 前缀偏好/队列，**不动**凭证库；凭证的清除入口唯一收敛到本卡（+ 退出登录）。

### 5.4 其他

- TopBar 菜单不动（「切换账号」「退出登录」），仅行为按 §3.4 落实。
- 多账号**不做数据隔离**：播放队列、最近搜索、主题偏好全局共用（与 v0.1.4 切换行为一致）；切换仅清 `likesStore` 缓存并 `dataVersion+1` 触发重拉。

## 6. 安全权衡（记录在案）

| 风险 | 说明 | 接受理由 |
|------|------|----------|
| 多凭证集中于 localStorage | 单凭证 → 最多 10 个凭证，XSS/恶意扩展/共享 profile 的爆炸半径变大 | v0.1.4 同域风险的量级放大，非新面；用户知情接受，且本版补上「可查看/可移除/可清空」的控制能力 |
| 切换保留旧凭证 = 旧账号长期可恢复 | 浏览器被他人使用时可直接切入任意已保存账号 | 单人自用机器；缓解：弹窗/设置可逐个移除 + 清空，「退出登录」彻底吊销 |
| 「清除本地数据」不清凭证 | 用户误以为已清干净 | 文案在「账号凭证」卡明确提示；备选是合并清除，代价是「清偏好」顺带掉登录，体验更差 |
| restore 接口可凭任意有效凭证建会话 | 不变（v0.1.4 已接受） | 能力等同登录接口；仅绑定 localhost |
| 凭证明文过传输层 | 不变，仅 localhost | v0.1.4 结论沿用 |

不做的缓解（沿用 v0.1.4 §6）：DPAPI/加密存储、HttpOnly 承载凭证、多账号独立加密容器。

## 7. 非目标（本版明确不做）

1. **凭证加密存储**：同 v0.1.4 结论，固定密钥加密防不了本机攻击者。
2. **多账号同时在线 / 数据隔离**：单活跃账号模型，其余账号只是「凭证存根」；队列、喜欢、听歌排行不按账号分仓。
3. **凭证自动续期**：MUSIC_U / MUSIC_A_T 过期后该账号需重新扫码（上游限制），本版只保证「未过期就不用扫」。
4. **会话收紧（drop 旧 sid）**：备选方案见 §3.3 c，默认不做。
5. **凭证导入导出 / 云同步 / 跨浏览器迁移**：凭证不出浏览器信任域。
6. **账号备注、排序、分组**：列表按 `lastUsedAt` 排序即够用。

## 10. 实施补记（决策微调，与上文冲突处以本节为准）

### 10.1 S0-1 结论：`/logout` 吊销语义

**结论：吊销，按 §3.4「彻底退出」落地。** 依据：`auth_service.logout()` 调用的上游 `logout` 即网易云官方「退出登录」接口（以账号 cookie 调用，令牌随服务端登出作废），与 v0.1.4 注释及验收语义一致；公开资料检索未见「logout 后 cookie 仍可用」的反例。真实账号实测（登出后拿原凭证调 `restore` 应得 401）列入 §8 S4 / 验收时人工复核；若实测不吊销，「彻底退出」退化为仅本地删除凭证（§3.3 备选路径仍成立）。→ **v0.1.5 验收通过**：「退出登录」后被退出账号须重新扫码（§9 第 4 项），吊销语义成立。

### 10.2 `activeId` 允许为 null（§3.2 / §4.1 微调）

存储信封 `{ v, activeId, accounts }` 中 `activeId: number | null`：

- 移除 / 退出 active 账号后 **置 null、不自动顶替**，下次冷启动不「变成另一个人」（§3.5 决策的自然延伸）；由用户点选后重新置 active；
- v1 迁移条目 `userId: 0` 仍可作为 active（`activeId: 0` ≠ `null`），保证「升级后免扫码进入」成立。

### 10.3 「清除全部凭证」的语义（§5.3 补充）

= **当前账号走 `logout()`（上游吊销）+ 其余条目纯本地删除**。若只删本地条目而不结束会话，sid cookie 仍有效，刷新页面会「复活」登录态，与 §9「清除全部后刷新只能扫码」冲突。单个「移除」仍为纯本地删除、不吊销（仅移除当前账号例外，见 §3.4）。

### 10.4 切换弹窗登录成功后整页刷新（验收反馈）

切换账号弹窗内**任一登录成功路径**（点已保存账号一键切换 / 扫码新增登录）→ `window.location.reload()` 整页刷新，当前页（如设置页）内容与新账号保持一致。原「弹窗关闭、留在当前页 + `dataVersion` 自愈」仅保留给 401 自动恢复路径（`dataVersion` 机制不变）。刷新后队列/音量等偏好按 v0.1.2 持久化规则恢复；`MainLayout` 挂载时按 `dataVersion` 重拉红心等数据。登录页（`/login`）的扫码/快速登录不走刷新（随后即 `navigate('/home')` 整页重挂载）。

- 恢复去重键：`userId > 0 ? id:userId : cred:MUSIC_U`（v1 迁移条目 userId 暂缺时退化用 MUSIC_U，避免不同条目被误合并）。
- 存储层验收要点已用脚本走查 25 项断言全通过（迁移 / 判重 / LRU / 损坏与禁用降级）；脚本为临时验证用、不入库。

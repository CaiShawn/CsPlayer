## S1 分享卡片（核心）

### 1.1 需求决策（2026-10，已与需求方确认）

| 项 | 决策 |
|---|---|
| 对象与差异 | 单曲 / 专辑 / 歌单统一版式家族，差异只在字段（见 §1.4 内容集） |
| 版式 | **导出比例用户可选（5 档）**：竖版 1:1（1080×1080）/ 3:4（1080×1440，默认）/ 9:16（1080×1920）；横版 4:3（1440×1080）/ 16:9（1920×1080）——横版用横排双栏布局，见 §1.4 |
| 内容元素 | 大封面 + 类型徽标（单曲/专辑/歌单）+ 标题 + 副题 + 元信息（歌曲数 / 时长）+ 可选**个人评论**（引用体，固定在卡片底部原落款行位置，见 §1.10） |

| 落款 | ~~底部品牌行~~（第三轮反馈：**已删除**，底部不再放品牌信息） |
| 背景样式 | **渐变海报底（默认）/ 纯色**（近黑 #101010）弹窗内二选一 |

**内容集（基础集，第三轮反馈定稿）**：

| 对象 | 副题 | 元信息行 |
|---|---|---|
| 单曲 | 歌手（多歌手 `/` 连接） | 专辑名 · 时长（mm:ss） |
| 专辑 | 歌手 | N 首 · 总时长（h:mm:ss） |

### 1.3 技术方案对比与决策

**渲染技术**：

| 候选 | 说明 | 结论 |
|---|---|---|
| a. DOM + 截图库（html2canvas / html-to-image / modern-screenshot） | 复用 Tailwind 样式再栅格化 | ❌ 引依赖；Tailwind 类 / CSS 变量 / 字体渲染保真不可控；跨域图片同样污染 canvas，问题不减 |
| **b. 手绘 canvas 2D（决策）** | 三种比例 = 同一参数化布局函数；`renderShareCard(ctx, spec)` 纯函数 | ✅ 零依赖、输出确定、精确控制；代价约 300 行绘制代码 + 手工文本测量换行 |

**封面 CORS 策略（S1-1 探测，两分支）**：

1. 探测方法（开发时一次性，结论回填本文档）：真实封面 URL 以 `crossOrigin='anonymous'` 加载后尝试 `canvas.toDataURL()`——成功 = CDN 返回 ACAO 头。
2. **✅ 已探测（2026-09-25 回填）：CDN 返回 `Access-Control-Allow-Origin: *`（带/不带 Origin 头均返回，GET 直连实测）→ 纯前端直连，S1 保持后端零改动（符合 v0.1.8 版本预期）。**
3. 不通分支（未触发，备档）：本版封面降级为主题色占位块（`neutral-800` 底 + ♪ 字形），不擅自加后端接口；后端图片代理（~30 行白名单 `music.126.net` 字节转发）作为升级候选单独请示后再做。
4. 无论分支，封面像素获取**单点封装**在 `utils/coverImage.ts`（`loadCoverImage(url): Promise<HTMLImageElement | null>`，模块级缓存，失败返回 null）——若后续引入代理或 v0.2.0 迁移，只改这一处。

**导出流程**：预览 canvas 与导出同一渲染函数；预览按显示宽度缩放（devicePixelRatio 适配防锯齿），导出固定像素尺寸（1080 基准）。下载：`canvas.toBlob('image/jpeg', 0.92)` → `a[download]`，文件名 `CsPlayer - {标题} {宽}x{高}.jpg`（如 `CsPlayer - 海阔天空 1080x1920.jpg`；Windows 非法字符 `\ / : * ? " < > |` 清洗）。导出格式统一 **JPG**（第七/八轮反馈定稿，体积红线约束已撤，固定画质 0.92）。

### 1.4 版式与布局系统

统一单栏布局（三种比例只是 W/H 不同，同一函数）：

```
┌──────────────────────────┐
│  padding = W × 7%        │
│   ┌──────────────────┐   │  封面 S = min(W−2P, H×0.55)
│   │      封面         │   │  圆角 28px；无封面 → 占位块
│   └──────────────────┘   │
│   〔类型徽标 pill〕        │  accent 底 + 深色字（bg-accent 语义）
│   标题（最多 2 行，省略号） │  neutral-50，粗体；measureText 手工换行
│   副题（1 行，省略号）     │  neutral-300
│   元信息行（1 行）         │  neutral-400
│   元信息                     │  neutral-400
│   （弹性留白）              │
│   ▎个人评论（可选，固定底部）│  accent 竖线 + 浅色文字，原落款行位置
└──────────────────────────┘
```

- 背景两层：对角线性渐变海报底（#141414→#0a0a0a）+ accent 低透明度径向渐变（主题感）。
- 徽标、评论竖线、径向渐变三处使用 accent；其余全部中性色——任何主题色下都协调。
- 字体：系统字体栈（`system-ui, "PingFang SC", "Microsoft YaHei", sans-serif`），跨 OS 渲染差异接受。

### 1.9 实施补记（2026-10，S1 落地时决策）

1. **专辑 Brief 需一次补拉**：专辑 `AlbumBrief` 无曲目数（无法出「N 首 · 总时长」元信息）——右键分享专辑时弹窗补拉一次 `albumDetail`（服务端缓存 300s，体感无感）；单曲 / 歌单仍零调用。（第三轮一度随元信息移除而删，同轮即随元信息恢复而恢复）
2. **专辑源用结构化最小类型** `AlbumCardData`（Pick id/name/coverUrl/artistName/tracks）：专辑页状态是内联裁剪型（无 artistId/publishTime），结构化类型同时兼容两形态，不动页面既有代码。
3. 动作图标 `◫`（与现有单字符图标风格一致）；默认比例 3:4；预览显示宽 320px。
4. 布局自适应：封面先按 `min(W−2P, H×0.55)` 上限，再按「最坏 2 行标题 + 页边」逐档收缩（下限 W×0.38），内容块整体垂直居中——三比例共用一套数学，无需分形态硬编码。

### 1.10 第二轮补记（2026-10：横版 + 个人评论 + 样式精修，需求方已确认）

**横版比例（4:3 / 16:9，两档都加）**：横版不是竖版拉宽，而是**横排双栏布局**——封面左（占高、且不超过版面宽 40%），文案右列垂直居中，共用同一文本栈绘制器（横版字号体系略大：标题 54/72）。展示顺序：方 → 竖 → 横 → 长。

**个人评论（可选）**：弹窗新增输入框（限 48 字，实时预览，字数计数）；渲染为**引用体**——accent 竖线（5px 圆角）+ 浅色文字（#e5e5e5）。**位置（第四轮反馈定稿）：固定渲染在卡片底部原落款行位置**（左下、末行贴底边距向上生长；竖 / 横版同位；评论区从内容区预留空间，无评论时内容区即全页）；不在文本栈内，最多 2 行折行省略，留空不占位；评论不进 ShareCardSource（不入库、不持久化，仅当次导出）。导出按钮文案：**「下载到本地」**。

**第三轮反馈（2026-10）**：① 底部品牌落款行**删除**（布局预留 FOOTER_ZONE 同步移除，位置让给个人评论，见下）；② 元信息行**保留**（此前一轮误删，已恢复含专辑补拉链路）；③ 按钮文案改「下载到本地」。

**第六轮反馈（2026-10）**：导出格式统一 **JPG**（体积红线后于第八轮撤销，固定画质 0.92）。

**样式精修（细节 + 海报底，两者都要）**：

- 背景：纯黑 → **对角线性渐变海报底**（#181818 → #0a0a0a）+ accent 三层光晕（**自底部上升 16%**（大片留白区最显眼，第九轮反馈加强）+ 封面外围径向（中段 8% 保持可见）+ 右下角 8%）；注意封面径向中心会被大封面遮挡，可见性不依赖它；
- 封面：柔和投影（圆角矩形预投 + shadowBlur 6%）+ 1px 微描边（白 8%）；
- 排印：标题 1px 字距（新内核 letterSpacing，旧内核忽略）、元信息前置 accent 分隔点；
- 无障碍：以上全部纯视觉，不引入新状态与设置项。

## S2 唱片架（细化定稿 2026-10，决策已与需求方确认）

核心：`ShelfPage` 收藏专辑展示从普通封面网格升级为**质感网格唱片架** + **搜索** + **hover 多选** + **选中专辑拼贴卡分享**（与 S1 共享渲染与导出链路）。「整面墙分享」标为可延伸，本期不做。

### 2.1 需求决策（已确认）

| 项 | 决策 |
|---|---|
| 视觉形态 | **质感网格**：保持现有响应式网格（2/3/4/5 列），加层次投影、封面光泽、hover 浮起；不引入黑胶外露/搁架，克制不抢戏 |
| 排序 | **保持收藏顺序**（接口即按收藏顺序分页，不引入排序 UI） |
| 搜索 | Shelf 页头下加搜索框，前端过滤（名称/歌手包含匹配，不区分大小写）；**首搜自动补齐全量**（仅搜已加载会漏掉未滚动部分，结果不可信；limit=200 分批边拉边显、内存缓存、清空即停）；补齐中显示进度；过滤态隐藏无限滚动哨兵 |
| 多选 | **hover 勾选圈**：hover 封面时左上角浮现勾选圈，点击选中（不导航）；选中 ≥1 张后底部浮出操作条，此态下勾选圈常驻、点击封面即切换选中；清空/退出恢复普通浏览（点击恢复导航） |
| 分享 | 选中 **2–20 张** → **一张拼贴卡**（网格拼贴，复用 S1 的背景/评论/色板/比例/导出链路）；单张分享走现有 S1 卡片（右键菜单已覆盖），拼贴弹窗内不再提供逐张导出 |
| 整面墙分享 | 可延伸，本期不做 |
| 性能 | 沿用无限滚动，**本期不引入虚拟化**；虚拟化方案作为附记存档（§2.6），触发阈值 >500 张再评估 |

### 2.2 现状勘查

| 关注点 | 现状 | 结论 |
|---|---|---|
| 数据 | `/api/user/albums` offset 分页（PAGE_SIZE=40），按收藏顺序返回 `AlbumBrief[]`（id/name/coverUrl/artistName） | 前端过滤即可，零后端改动 |
| 页面 | `ShelfPage.tsx`：无限滚动（`useInfiniteScroll`）+ 断链重试 + 右键菜单 + Cover 组件 | 网格类名与卡片结构小改，加载模型不动 |
| 渲染复用 | S1 `shareCard.ts`：drawBackground（渐变/纯色已支持 bgStyle）、drawCover、drawStack、评论置底、`exportShareCardBlob`（JPG） | 拼贴卡 = 新 `buildCollageSpec` + `renderCollageCard`，复用背景/评论/导出，预计 ~150 行 |
| 弹窗复用 | `ShareCardModal` 已有比例/评论/色板/背景切换 | `uiStore.shareSource` 增加 `kind: 'collage'` 变体，弹窗内分支渲染拼贴 |
| 封面像素 | `loadCoverImage`（模块级缓存，失败返回 null → 占位） | 2–6 张并行 `Promise.all`，失败的出占位 |

### 2.3 视觉规格（质感网格，纯 CSS）

- 封面投影：`shadow-lg shadow-black/40`，hover 增强 + `translate-y-[-4px]`（200ms 过渡）；
- 光泽：封面右上斜向高光伪元素（白 4% → 0 线性渐变），hover 时透明度提升；
- 圆角沿用 `var(--radius-cover)`，卡片内衬边框现状保留；
- 勾选圈：左上角 22px 圆圈，未选中半透明描边、选中实心 accent + ✓；选中态卡片**不加描边**，以背景变色区分（accent 15% 底，验收反馈）。

### 2.4 拼贴卡版式
- 画布：**尺寸随张数自适应，不提供比例选择**（验收反馈：固定比例下非 1:1 档留死边不均匀）；**取向横/竖可切换**（竖=round(√N) 列、横=ceil(√N) 列，正方形张数两取向相同）——如 5 张：竖 2×3（1080×1548）/ 横 3×2（1080×768）、20 张：竖 4×5（1080×1314）/ 横 5×4（1080×893）（有评论时画布相应增高）；主体为封面网格（无任何文字元素，封面无缝平铺：无间隙、直角、无投影描边）：
- 行列布局（collageGrid）：2 张=2×1；3–4 张=2×2；5–9 张=3 列（5–6 两行、7–9 三行）；末行不足时居中；1 张不支持（走 S1 单卡），上限 9 张；
- 文本：顶部徽标「唱片架」+ 标题「我的唱片架」（或空态默认）+ 元信息「N 张专辑」；评论引用体置底（同 S1）；
- 背景渐变/纯色、accent 色板、导出 JPG 全部复用 S1 控件与链路。

### 2.6 附记：虚拟化方案（本期不实施，>500 张再评估）

- **现状边界**：无限滚动 DOM 累积，1000 张 ≈ 5000 节点，Chromium 可承受但长列表滚动内存上涨；
- **方案 A 自研窗口化**：ResizeObserver 测行高 → 计算 visible range → 上下占位撑高；列数响应式变化需重算，黑胶/hover 动效不受影响；约 2 人日；
- **方案 B react-virtuoso**（推荐）：原生支持响应式网格 + 增量渲染（~15KB），接入点为替换 grid 容器与 `useInfiniteScroll`，约 1 人日；
- 决策：质感网格为纯视觉升级不改变加载模型，现收藏量级（≤500）无感知差异，暂不动。
